# vox-mcp — Vox-style explainer videos over MCP

An MCP server that lets any text-only LLM produce a narrated, Vox-style
motion-graphics explainer. Nothing is generated by a video model: every frame
is a coded Remotion template, the narration comes from ElevenLabs, and the
output is one MP4.

```
Text-only LLM ──MCP tool calls──▶  Vox video MCP server
                                   ├─ Script tools  → project files (scene JSON, assets)
                                   ├─ Voice tools   → ElevenLabs (voice + word timestamps)
                                   └─ Render tools  → Remotion (Vox templates → preview, MP4)
                                                              │
                                                              ▼
                                                       MP4 explainer
```

## What the agent gets

**Skills** — the editorial method, so any agent can make a good one, not just a
valid one:

| Kind | Name | What it is |
|---|---|---|
| prompt | `vox_explainer` | Loads the workflow + house style and starts a run on a topic |
| resource | `vox://guide/workflow` | Brief, research, script rules, storyboard rules, the single approval gate |
| resource | `vox://guide/style/newsroom` | Palette, type, motion vocabulary, what each template is for |
| resource | `vox://scene-types` | JSON Schema for every scene template |
| tool | `vox_get_guide` | The same guides as a tool, for clients without prompt/resource support |

**Script tools**

| Tool | Does |
|---|---|
| `vox_list_scene_types` | The 10 templates and their fields |
| `vox_save_project` | Validate and store the storyboard; returns house-rule warnings |
| `vox_get_project` / `vox_list_projects` | Read back state, including which blocks have narration |
| `vox_add_asset` | Pull an image or audio file in from a URL or local path |
| `vox_plan_timing` | Per-block durations, runtime, ElevenLabs characters, remaining quota — the gate summary |

**Voice tools (ElevenLabs)**

| Tool | Does |
|---|---|
| `vox_list_voices` | Search the account's voices |
| `vox_synthesize_narration` | One TTS call per block with character timestamps → MP3 + word timings. Skips unchanged blocks |
| `vox_generate_music` | Instrumental bed via ElevenLabs Music; ducked under the voice automatically |

**Render tools (Remotion)**

| Tool | Does |
|---|---|
| `vox_render_preview` | One frame of a block, returned as an image so the model can look at it |
| `vox_render_video` | H.264/AAC MP4 in 9:16, 16:9 and/or 1:1 |
| `vox_render_status` | Poll long renders |

### Scene templates (newsroom house style)

`headline` · `stat` · `bar_chart` · `line_chart` · `comparison` · `list` ·
`quote` · `timeline` · `image` (halftone cutout, optional map pins) · `end_card`

Every block is: one narration line + one scene. Block length comes from the
real narration audio (plus a short lead-in and tail), captions are synced word
by word from ElevenLabs timestamps, and the archival-paper stage persists
across blocks while each scene whips in and out.

## Requirements

- Node 20+
- An ElevenLabs API key (only for the voice tools; previews and silent renders work without one)
- Network on first render: Remotion downloads Chrome Headless Shell (~100 MB) once, and
  the templates load Anton, Source Serif 4 and Special Elite from Google Fonts
- Linux, macOS or Windows. Rendering is local and CPU-bound; a one-minute
  1080×1920 video took ~90 s in testing

## Install

```bash
git clone https://github.com/bala2006/vox-style-power.git
cd vox-style-power/mcp-server
npm install        # also builds dist/
```

## Connect it to an agent

The server speaks MCP over stdio. Every client takes the same three things:
`command`, `args` and `env`.

```json
{
  "mcpServers": {
    "vox": {
      "command": "node",
      "args": ["/absolute/path/to/vox-style-power/mcp-server/dist/index.js"],
      "env": {
        "ELEVENLABS_API_KEY": "sk_...",
        "VOX_OUTPUT_DIR": "/absolute/path/to/vox-output"
      }
    }
  }
}
```

| Client | Where that JSON goes |
|---|---|
| Claude Desktop | `claude_desktop_config.json` (Settings → Developer → Edit config) |
| Cursor | `.cursor/mcp.json` or `~/.cursor/mcp.json` |
| Kiro | `.kiro/settings/mcp.json` or `~/.kiro/settings/mcp.json` |
| VS Code / Copilot | `.vscode/mcp.json` (top-level key is `servers` there) |
| Claude Code | `claude mcp add vox -e ELEVENLABS_API_KEY=sk_... -- node /abs/path/mcp-server/dist/index.js` |

Then ask the agent: *"Use the vox tools to make a one-minute vertical
explainer about why GPU prices fell."* Agents that support MCP prompts can
also start from the `vox_explainer` prompt.

### Environment

| Variable | Default | Purpose |
|---|---|---|
| `ELEVENLABS_API_KEY` | — | Required for voice and music tools |
| `VOX_OUTPUT_DIR` | `~/vox-output` | Where projects, audio and renders are written |
| `VOX_VOICE_ID` | — | Default narrator when a project does not set `voice.voice_id` |
| `VOX_TTS_MODEL` | `eleven_multilingual_v2` | Default ElevenLabs TTS model |
| `ELEVENLABS_BASE_URL` | `https://api.elevenlabs.io` | e.g. a data-residency endpoint |
| `VOX_RENDER_CONCURRENCY` | Remotion default | Parallel frames per render |
| `VOX_RENDER_CRF` | `23` | H.264 quality; lower is larger and sharper |

## The flow an agent follows

1. Brief → research (two sources per number) → script (~20–24 words per block)
2. `vox_save_project` → fix warnings → `vox_render_preview` each block
3. **Gate:** `vox_plan_timing`, show script + previews + estimate, wait for a yes
4. `vox_synthesize_narration` → optional `vox_generate_music`
5. `vox_render_video` → `vox_render_status` until done

No ElevenLabs credit is spent before step 4; the guide tells the agent so and
the voice tools say so in their descriptions.

## Project layout on disk

```
<VOX_OUTPUT_DIR>/<slug>/
  project.json            the storyboard
  assets/                 images, music
  audio/block-01.mp3      narration per block
  audio/block-01.json     word timings + the text they were made from
  renders/                preview JPEGs and final MP4s
```

## Development

```bash
npm run build          # compile the server
npm run studio         # open Remotion Studio on the sample storyboard
npm run smoke          # end-to-end test over real MCP stdio with a mock ElevenLabs API
node scripts/smoke.mjs --aspect=16:9   # silent run, landscape
```

The smoke test spawns the server, saves a storyboard, adds an asset,
synthesizes against a local mock of the ElevenLabs endpoints, generates a
music bed, previews every block, renders the MP4, and checks there are no
silent blocks. It writes to `./vox-output-smoke` and spends no credits.

## Security notes

- The API key is read from the environment only; it is never written to disk,
  logged, or returned in tool output.
- Assets are served to the headless browser from a loopback-only HTTP server
  that exposes nothing but each project's `assets/` and `audio/` folders.
- Slugs and asset names are sanitised; assets are limited to 50 MB and to
  image/audio file types.
