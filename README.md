# vox-style

Turn a topic, a trend, an article, or nothing at all into a **finished narrated
motion-graphics explainer video**. One approval gate with a credit estimate, then
the style key, the voiceover, the clips and one assembled MP4.

Two backends, picked in the wizard:

- **Higgsfield MCP** — fully automatic, nothing to do after the gate.
- **Google Flow, by hand** — the skill writes the prompts and the cut plan, you
  generate the clips, it assembles locally. **Zero Higgsfield credits.**

## Install

```
/plugin marketplace add AICreatorEngine/vox-style-skill
/plugin install vox-style@vox
```

Then run it with `/vox-style`, or just ask for "a video about X".

Both lines are needed — adding the marketplace registers the catalog, installing
picks the plugin out of it. There is no combined command. From a shell, without
the interactive panel:

```bash
claude plugin marketplace add AICreatorEngine/vox-style-skill
claude plugin install vox-style@vox
```

### Turn auto-update on, it is off by default

The plugin declares **no pinned version**, so every commit pushed here counts as
a new version. But **third-party marketplaces ship with auto-update disabled** —
only Anthropic's official ones have it on. Enable it once:

```
/plugin            →  Marketplaces  →  vox  →  Enable auto-update
```

Until you do, pull updates by hand:

```
/plugin marketplace update vox
```

### For a team

Put this in the project's `.claude/settings.json` and teammates are prompted to
install it when they trust the folder, instead of typing anything:

```json
{
  "extraKnownMarketplaces": {
    "vox": {
      "source": { "source": "github", "repo": "AICreatorEngine/vox-style-skill" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": ["vox-style@vox"]
}
```

## What you need

Only for the Higgsfield backend — the Flow path needs none of it.

```
claude mcp add --transport http --scope user higgsfield https://mcp.higgsfield.ai/mcp
```

then `/mcp` once to authenticate. There are no API keys in this project by
design.

The local scripts (`assemble.py`, `build-ad.py`, `restore-sound-bed.py`) need
`ffmpeg` on PATH and `Pillow`. Server-side assembly needs neither.

## The six modes

| Mode | What you get |
|---|---|
| **A. Explainer** | One finished MP4 from a topic, a trend, a URL, or nothing |
| **B. Style key** | A permanent custom look for a new series or brand |
| **C. News radar** | Three scored story candidates, then it stops |
| **D. Business** | A problem → product → CTA video about your own offer |
| **E. Series** | A bible, bookends, an episode slate, and episode one |
| **F. Manual build** | Any of the above, generated by hand in Flow for zero credits |

The wizard's first question picks the mode; its second picks the backend.

## What the skill actually knows

Most of this file is not instructions, it is **defects that shipped once and
were then measured**. A few:

- `explainer_video` **replaces** clip audio with the voice take, it does not mix.
  The deliverable is narration over digital silence unless the bed is rebuilt,
  and every casual check passes.
- Generators return wildly different audio levels per clip — 17 dB across five
  clips on one run — so the bed has to be normalised per clip before ducking.
- A ducking release longer than the gaps between phrases keeps the bed down for
  the whole film.
- `gemini_omni` does **not** inherit aspect from the style key. Pass
  `aspect_ratio` on every clip.
- Veo Quality **cannot take reference images**, so it cannot hold a character
  across clips. Never buy it for "the hero shot".
- Naming a forbidden thing in order to forbid it is enough to get an innocent
  prompt refused: there is no separate negative field, the whole prompt goes to
  one classifier.
- Burned captions and generated props both live in the lower third and collide
  by default.

Each of those carries the date it was verified on a real run.
